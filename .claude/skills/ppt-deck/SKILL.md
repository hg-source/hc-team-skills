# PPT덱 (ppt-deck)

스토리보드부터 완성까지 **매 단계 사용자 게이트**를 거치는 협업형 덱 제작. visual-deck(한 번에 위임)과 반대 방향의 스킬이다.

## 불변 원칙

1. **단계별 게이트**: 각 단계 산출물을 보여주고 사용자 확인 후 다음 단계로. 사용자가 "한 번에 끝까지"라고 명시할 때만 게이트 생략.
2. **HTML이 정본, PPT/PDF는 파생물**: 변환은 최종본 확정 후 사용자가 요청할 때만.
3. **레이아웃 라이브러리로만 조립**: 모든 슬라이드는 [assets/layout-library.html](assets/layout-library.html)의 19종 중 하나이며 `<section data-layout="...">` 속성을 반드시 유지한다(내보내기 매핑 키). 블록 안의 디자인은 자유, 블록 구조는 고정.
4. **시트 조작은 스크립트로만**: [scripts/storyboard.mjs](scripts/storyboard.mjs) 경유. 직접 gws 호출 금지.

## 작업 폴더

덱 하나당 `work/ppt-deck-<주제>-<YYYYMMDD>/` 생성:

```
deck-config.json   # { title, spreadsheetId, sheetUrl, createdAt, stage }
draft.html         # 2단계 와이어프레임 초안
deck.html          # 3~4단계 정본
exports/           # 내보내기 산출물 (.pptx/.pdf)
```

## 4단계 워크플로우

### 1단계 — 스토리보드 (구글 시트)

1. `node scripts/storyboard.mjs create --title "덱 제목"` → 시트 생성, URL을 사용자에게 전달. (시트에는 "스토리보드" 탭 + "레이아웃 안내" 탭이 만들어짐. 레이아웃유형 열은 드롭다운.)
2. 사용자가 시트에 페이지별 `목차구분 · 슬라이드 제목 · 헤드라인 · 근거1~4`를 채운다. 대화로 함께 설계해달라고 하면 논의 내용을 Claude가 시트에 기입해도 된다(storyboard.mjs 외 값 기입은 사용자가 요청한 경우만).
3. 사용자가 "채웠다"고 하면 `read --sheet <url>`로 회수 → 각 행의 헤드라인·근거 성격을 판독해 레이아웃유형을 제안하고 `propose --sheet <url> --rows <제안.json>`으로 기입(제안근거 열에 이유 1줄 포함, 이미 채워진 행은 건너뜀).
4. 사용자가 시트에서 레이아웃을 검토·수정 → 확정 신호를 받으면 `read`로 최종 스토리보드를 회수하고 2단계로.

### 2단계 — 와이어프레임 초안 (draft.html)

- layout-library.html의 셸(네비게이션·인쇄 CSS)과 해당 유형 와이어프레임 마크업을 그대로 사용해 `draft.html` 생성.
- **채우는 것**: 실제 슬라이드 제목·헤드라인·근거 텍스트(시트 값 그대로), 목차(목차구분에서 생성).
- **채우지 않는 것**: 도식·차트·이미지·세부 본문 — 회색 placeholder 존으로 남긴다.
- 사용자와 페이지별로 리뷰: 순서·레이아웃·헤드라인 조정. 시트와 draft.html 중 정본은 이 시점부터 draft.html(시트로 역반영은 하지 않음).

### 3단계 — 세부 작성 (deck.html)

- **목차구분(섹션) 단위로 승인→채우기 루프**: 한 섹션을 완성해 보여주고 확인받은 뒤 다음 섹션으로. 긴 덱에서 전량 일괄 작성 금지.
- 시각 언어는 visual-deck의 executive-minimal을 따른다: 결론형 제목, 장당 판단 1개, 플랫 편집 구성, 강조는 핵심 비교 1개에만, 데이터에 기간·단위·출처 표기.
- 도식·차트는 HTML/SVG로 직접 작도(이미지 캡처 금지). 이미지는 사용자 제공 파일만 삽입.
- 헤드라인 문구는 본문 근거보다 강하게 쓰지 않는다(과장 금지 원칙).

### 4단계 — 최종 확정 · 내보내기

- 사용자 최종 수정 의견을 deck.html에 반영해 확정.
- **내보내기는 요청 시에만**. 용도 확인: 공유·인쇄용이면 PDF(브라우저 인쇄, `@media print` 내장) 권장, 받는 쪽이 PPT에서 직접 수정해야 할 때만 PPTX.
- PPTX 생성: `scripts/pptx-deck-builder.js` 사용(표는 colW 배열 + `writeAndVerify` 필수). deck.html의 `data-layout`별로 매핑 스크립트를 작성해 편집 가능한 네이티브 요소로 재구성한다 — cover/bridge=배경+대형 텍스트, bullets/cards-N/summary/conclusion=텍스트 박스 그리드, matrix/비교표=D.table, kpi=대형 숫자 텍스트, chart=pptxgenjs 네이티브 차트, timeline/process/quad/diagram=도형+선, media=이미지+텍스트, quote=인용 타이포.
- 내보낸 파일을 최종 HTML과 대조해 불가피한 차이를 보고한다.

## 레이아웃 라이브러리 (19종)

정의·와이어프레임·`data-layout` 코드는 [assets/layout-library.html](assets/layout-library.html)이 정본. 시트 드롭다운 값과 코드 대응은 `storyboard.mjs layouts`로 확인.

- 구조: 표지 · 목차 · 요약(Executive Summary, 덱 2페이지) · 섹션브릿지 · 결론/권고
- 본문: 불릿 · 2/3/4단카드 · 2단대비 · 비교표 · 2x2 · KPI · 차트+해설 · 이미지+텍스트 · 인용/VOC · 타임라인 · 프로세스 · 도식
- **변형 흡수 규칙**(새 유형 추가 금지): 빅넘버·대시보드→KPI, 퍼널→프로세스, 워터폴→차트+해설, 하비볼 스코어카드→비교표. 실전에서 반복적으로 필요해질 때만 라이브러리에 유형을 추가한다.

## 레이아웃 제안 기준 (1단계 3번)

- 근거가 수치 위주 1~4개 → KPI / 추세·비교 데이터 → 차트+해설
- 근거가 대등한 항목 나열 → N단카드(개수=단수) / 대립 구도 → 2단대비
- 다항목×다기준 → 비교표 / 2축 분류·우선순위 → 2x2
- 시간 흐름 → 타임라인 / 절차·전환 → 프로세스 / 정적 구조 → 도식
- 고객 발화 인용 → 인용/VOC / 제품·화면 보여주기 → 이미지+텍스트
- 판단 애매하면 불릿(기본형)으로 제안하고 제안근거에 대안 유형을 병기.

## 선택 기능 의존성

- Google Sheets 스토리보드는 별도로 설치·인증된 `gws` CLI가 있을 때 사용한다.
- 편집형 PPTX 내보내기는 최초 1회 `scripts` 폴더에서 `npm install`을 실행해 고정된 의존성을 설치한다. HTML 정본 작성에는 이 설치가 필요 없다.

## 최소 검증

16:9 슬라이드 핏, 네비게이션 v2(하단 중앙 롤오버 컨트롤 바 ← n/N → ⛶ ▦ · 좌우 30% 클릭 넘김 존 · 첫/끝 페이지 존 비활성 · 키보드 ←→/O/F · 스와이프 · 오버뷰), 페이지 수/진행 표시, 인쇄 레이아웃, JS 문법, `data-layout` 누락 여부, 외부 공유 시 내부 경로·민감정보 제거. PPTX 내보내기 시 `writeAndVerify` 통과 확인. 덱은 layout-library.html의 셸(컨트롤 마크업·CSS·JS)을 그대로 상속한다.
