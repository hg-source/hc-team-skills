# Layout Catalog

레이아웃은 페이지의 **역할**에 따라 선택한다. 아래 이름을 plan JSON의 `layout_family`로 사용한다.

## Narrative

### `editorial-cover`
- 큰 주장/보고 주제 + 짧은 subtitle + 한 개의 시각 anchor
- 금지: 여러 metric card, 장황한 목차

### `editorial-summary`
- 결론 3개를 수평 claim band로 배열하고 마지막에 decision band
- 숫자보다 결정이 우선일 때 사용

### `section-divider`
- 섹션 전환에만 사용. 1개의 statement와 여백 중심

## Evidence

### `annotated-chart`
- 주 chart 1개 + 변곡점 annotation + so-what
- chart가 없는 경우 사용하지 않는다.

### `variance-bridge`
- base → lever → target 또는 before → after
- 각 단계의 단위와 출처를 표시한다.

### `evidence-strip`
- 2~3개 핵심 수치를 한 방향으로 읽히게 연결
- 각 수치 아래 비교 기준·한계를 쓴다.

### `contrast-table`
- 복잡한 비교가 필요할 때만 native table 사용
- 강조 행은 최대 2개

## Decision

### `decision-tree`
- 조건→선택지→결정. 분기 수는 3개 이하

### `portfolio-map`
- 상품·사업을 2축 또는 Gate sequence에 배치
- 축이 주관적이면 '검토안'을 명시한다.

### `risk-map`
- 영향도×발생가능성 또는 controllable×uncontrollable
- 정량 근거가 없으면 high/medium/low를 사실처럼 쓰지 않는다.

## Operating Model

### `ownership-map`
- P&L owner, functional owner, execution team의 책임 경계
- 조직도보다 누가 무엇을 결정하는지 우선한다.

### `staggered-milestones`
- 30·60·90일, Gate 1·2·3처럼 선후관계를 계단형으로 배치
- 모든 단계를 같은 크기 box로 만들지 않는다.

### `owner-deadline-rows`
- 실행항목·오너·기한·완료조건을 rule로 구분한 행
- card가 아니라 편집형 표/목록 문법 사용

## Density Rhythm

7~8장 기준 권장 예:

1. sparse cover
2. medium summary
3. dense evidence
4. medium ownership
5. medium milestone
6. dense portfolio
7. sparse decision/action

같은 density와 layout family를 연속시키지 않는다.
