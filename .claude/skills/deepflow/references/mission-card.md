# MISSION.md — 스키마와 릴레이 기록 규칙

딥플로우가 과제 판독 직후 작업 폴더에 쓰는 단일 지휘 문서. 이 과제에 참여하는 모든 스킬(딥서치·딥솔루션·밤샘모드)이 시작 시 이 파일을 읽고, 단계가 끝날 때 자기 결과 행을 채운다. 경쟁 사본을 만들지 않는다 — 과제당 MISSION.md는 하나다.

## 위치

- 과제의 작업 폴더 루트에 둔다. 예: `10-projects/<과제명-YYYY-MM-DD>/MISSION.md` 또는 `work/<run_id>/MISSION.md`.
- 밤샘모드와 결합하면 밤샘모드의 `STATE.md` 등과 **같은 폴더**를 쓴다. MISSION.md는 계획·릴레이 원장, `STATE.md`는 현재 상태 스냅숏으로 역할이 다르며 서로를 대체하지 않는다.
- 재개 시(같은 run_id) 기존 MISSION.md를 읽고 이어서 쓴다. 새로 만들지 않는다.

## 스키마

```markdown
# MISSION: <과제 한 줄 제목>

- run_id: <고유 ID>
- 시작: <YYYY-MM-DD HH:mm KST>
- 실행 방식: 일반 | 밤샘 결합
- 상태 파일 경로: <STATE.md 등이 사는 폴더 절대/워크스페이스 경로>

## 판단문
<이 과제가 끝났을 때 답해야 할 질문 한 문장. 측정 가능하게.>

## 실행 계획
- 패턴: A | B | C | D (+ 변경 이력)
| 단계 | 스킬 | 모드/깊이 | 입력 | 종료 조건 | 다음 단계로 넘길 것 |
|---|---|---|---|---|---|
| 1 | deep-search | ... | 사용자 요청 + 기존 위키/리서치 | 핵심 질문 X·Y에 근거 확보 | 결론 요약 + 근거 위치 |
| 2 | deep-validation-flow | Standard | 1단계 산출물 | 판정 상태 도출 | 상태 + 브리프 위치 |

## 예산
- 전체 규모: <소(반나절) | 중(1일) | 대(밤샘)>
- 배분 원칙: <예: 탐색에 60%, 판단에 40%. 같은 깊이 중복 금지.>

## 릴레이 로그 (단계 종료마다 1행 추가)
| 시각(KST) | 단계 | 결과 신호 | 산출물 위치 | 딥플로우 결정 |
|---|---|---|---|---|

## 종료
- 최종 판정: <딥솔루션 상태 또는 조사 결론 요약>
- 판단문 답변 여부: 예 | 부분 | 아니오 (+ 부족분)
- 통합 보고 위치: <경로/URL>
```

## 작성 규칙

- **판단문이 최우선이다.** 판단문 없이 실행 계획을 쓰지 않는다. 사용자 요청이 모호하면 결론을 크게 바꾸는 조건(국가·대상·기간·예산)만 확인하고, 나머지는 가정을 판단문 아래 명시하고 진행한다.
- **모드 배정은 중복 방지 장치다.** 앞 단계가 깊이 판 영역은 뒷 단계 스킬에 "이 증거를 재사용하라"고 입력 열에 명시한다. 딥솔루션이 딥서치 결과를 받는 경우 기본 모드는 Standard이며, 반증·레드팀에서 증거가 부실하다고 판명될 때만 격상한다.
- **릴레이 로그는 append-only.** 지난 행을 고치지 않는다. 패턴 변경(예: C→D)은 실행 계획의 패턴 행에 이력을 덧붙이고 릴레이 로그에도 사유를 남긴다.
- 결과 신호는 각 스킬의 어휘를 그대로 쓴다. 딥솔루션은 6개 상태(`GO TO RESEARCH` 등), 딥서치는 완료/부분완료 + 결론 요약, 밤샘모드는 완료 정의 통과 여부.

## 릴레이 판정 기준

SKILL.md의 릴레이 표가 정본이다. 여기서는 판정 시 흔한 함정만 짚는다:

- **`GO TO RESEARCH` 재투입은 공백 한정 스코프로.** 딥솔루션이 명시한 증거 공백 목록만 딥서치에 넘긴다. "다시 전체 조사"로 확대하지 않는다.
- **같은 공백 2회 되돌이 = 웹의 한계.** 그 항목은 실측·인터뷰·견적 등 현장 검증으로 분류해 통합 보고의 "남은 검증"에 싣고 루프를 끊는다.
- **판정 격상 금지.** `GO TO VALIDATION`은 출시 승인이 아니고, `READY FOR DECISION`은 결정 완료가 아니다. 통합 보고에서 상태를 원문 그대로 옮긴다.
- **부분완료의 결정성 테스트.** 남은 범위가 판단문의 답을 바꿀 수 있는가? 바꿀 수 있으면 해소 단계를 추가하고, 없으면 한계로 기록하고 종료한다. 밤샘모드의 결정 변경 테스트와 같은 논리다.

## 종료 체크리스트

통합 보고 전 딥플로우가 확인한다:

1. 판단문 답변 여부가 예/부분/아니오로 기록됐다.
2. 릴레이 로그의 모든 행에 산출물 위치가 있고, 외부 저장(노션 등)은 재조회로 확인됐다.
3. 통합 보고가 단계 산출물을 복제하지 않고 링크한다.
4. 미해소 블로커·남은 현장 검증·기준일(KST)이 보고에 있다.
5. 밤샘 결합이면 `SUMMARY.md`와 통합 보고가 서로 모순되지 않는다.
