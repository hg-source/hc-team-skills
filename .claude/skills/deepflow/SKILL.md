# 딥플로우 (Deep Flow)

Version: 0.1.0+dayflo.1

시작 시 [공통 실행 규칙](references/common-runtime.md)을 읽는다. 앱별 경로·도구, 승인, 저장, 동시 작업의 기준이다.

중요하고 어려운 과제를 받아 **딥서치(탐색)·딥솔루션(판단)·밤샘모드(자율 실행)** 3종 중 무엇을, 어떤 순서로, 어떻게 조합해 쓸지 결정하고 끝까지 지휘하는 오케스트레이션 스킬.

## 역할과 경계

- 딥플로우는 **지휘자다. 내용 작업을 직접 하지 않는다.** 조사는 딥서치가, 원인 분석·가설 검증·대안 비교는 딥솔루션이, 장시간 무중단 실행은 밤샘모드가 한다. 딥플로우 자신의 산출물은 MISSION.md와 최종 통합 보고뿐이다.
- 각 스킬의 근거 기준·충분함 정의·권한 경계를 바꾸지 않는다. 딥플로우 호출 자체로 외부 발송·게시·구매·삭제 권한이 생기지 않는다.
- 지휘에 필요한 스킬은 가용 목록의 ID로 찾아 읽는다: `deep-search`, `deep-validation-flow`(표시명 딥솔루션), `night-mode`. 없는 스킬은 없다고 밝히고 현재 앱에서 가능한 대체 흐름으로 좁혀 진행하며, 읽지 않은 스킬을 실행했다고 하지 않는다.

## 발동 게이트

**나선다:**
- "딥플로우"를 지명한 호출.
- 목적이 복합이거나 모호한 중요 과제 — 탐색과 판단이 둘 다 필요해 보이거나, 사용자가 "알아서 깊고 넓게"라며 방식을 위임한 경우.
- 자리 비움 + 복합 과제(밤샘 결합이 필요한 다단계 작업).

**빠진다 (딥플로우를 거치지 않고 해당 스킬로 직행):**
- 사용자가 딥서치·딥솔루션·밤샘모드 중 하나를 직접 지명한 단일 요청.
- 단순 조회·요약·1스텝 수정. 이 경우 MISSION.md도 만들지 않는다.

## 과제 판독 — 두 축

라우팅은 두 축의 직교로 결정한다.

**축 1 — 모르는 것이 무엇인가 (목적 축):**

| 모르는 것 | 스킬 |
|---|---|
| 세상 (시장·고객·경쟁·트렌드·사실관계) | 딥서치 |
| 판단 (원인·대안·GO/NO-GO·우선순위) | 딥솔루션 |
| 둘 다 | 딥서치 → 딥솔루션 순차 |

**축 2 — 실행 방식 (실행 축, 목적 축과 독립):**

| 상황 | 방식 |
|---|---|
| 사용자가 옆에 있음 | 일반 실행 |
| 자리 비움 / 무중단 요청 | × 밤샘모드 (목적 스킬에 곱한다) |

밤샘모드는 선택지가 아니라 **곱하기 레이어**다. 목적 스킬을 먼저 정하고 실행 방식을 곱한다. 밤샘 결합은 사용자가 장시간 자율 실행을 요청하거나 자리 비움이 명확할 때만 하며, 추론으로 확대하지 않는다.

## 조합 패턴

| 패턴 | 흐름 | 전형 예 |
|---|---|---|
| A 탐색만 | 딥서치 | "이 시장 어떻게 돼 있어?" |
| B 판단만 | 딥솔루션 | 증거가 이미 손에 있고 선택만 남았을 때 |
| C 탐색→판단 | 딥서치 → 딥솔루션 | 신제품 검토, 사업성 검토 (가장 흔함) |
| D 되돌이 | 딥솔루션 → `GO TO RESEARCH` → 딥서치(공백 한정) → 딥솔루션 재개 | 판단 중 결정적 증거 공백 발견 |

패턴은 시작 시 확정하되, 단계 종료 신호에 따라 D처럼 바뀔 수 있다. 변경하면 MISSION.md에 사유와 함께 기록한다.

## MISSION.md — 딥플로우의 유일한 자기 산출물

과제 판독 후 작업 폴더에 `MISSION.md` 하나를 쓴다. 스키마·기록 규칙은 [mission-card.md](references/mission-card.md)를 따른다. 핵심 4요소:

1. **판단문** — 이 과제가 끝났을 때 답해야 할 질문 한 문장. 모든 단계의 종료 기준이 된다.
2. **실행 계획** — 패턴, 스킬 순서, 각 단계의 입력·종료 조건·다음 단계로 넘길 것.
3. **예산** — 전체 규모(시간·깊이)와 단계별 모드 배정. 딥서치가 깊이 팠으면 딥솔루션은 그 증거를 재사용하고 Standard로 시작하는 식으로, **같은 깊이를 두 번 파지 않는다.**
4. **상태 파일 단일 경로** — 이 과제의 `STATE.md`·`WORKLOG.md`·`DECISIONS.md`·`BLOCKERS.md`·`SUMMARY.md`가 사는 폴더 하나. 모든 단계 스킬이 이 한 세트를 재사용하며 경쟁 사본을 만들지 않는다.

## 바통 릴레이

각 단계 스킬의 종료 신호를 받아 다음을 결정한다. 신호를 사용자가 대신 읽고 다시 시켜야 하는 상황을 만들지 않는다.

| 받은 신호 | 딥플로우의 행동 |
|---|---|
| 딥서치 완료 (조사 결론) | 판단이 남았으면 결론·근거 위치를 입력으로 딥솔루션 투입. 탐색만이 목적이면 종료 절차로. |
| 딥솔루션 `GO TO RESEARCH` | 명시된 증거 공백**만** 스코프로 딥서치 재투입 → 완료 후 딥솔루션 재개 (패턴 D). |
| 딥솔루션 `GO TO VALIDATION` / `READY FOR DECISION` / `READY FOR EXECUTION` / `NO-GO` | 종료 절차로. 상태와 다음 게이트를 통합 보고에 그대로 싣는다. 판정을 격상하지 않는다. |
| 딥솔루션 `BLOCKED` / 밤샘 BLOCKERS 잔존 | 우회 가능하면 계획 수정 후 계속, 불가하면 부분완료로 종료하고 블로커를 명시. |
| 부분완료 | 남은 범위가 판단문에 결정적인가 판정. 결정적이면 해소 단계를 계획에 추가, 아니면 한계로 기록하고 진행. |

같은 단계가 같은 공백으로 2회 이상 되돌면 반복을 멈추고, 그 공백을 "웹으로 답할 수 없는 항목"(실측·인터뷰·견적 등)으로 분류해 사용자 몫으로 넘긴다.

## 운영 기본값

- **옆에 있을 때**: MISSION.md를 쓴 뒤 계획을 한 번 보여주고 출발한다. 이후 단계 전환은 보고만 하고 멈추지 않는다.
- **자리 비움 (×밤샘)**: MISSION.md만 쓰고 바로 출발한다. 계획 확인을 기다리지 않으며, 가정은 `DECISIONS.md`에 남긴다. 밤샘모드의 자율성 규칙·3관문·Stuck Protocol이 실행을 지배한다.
- 시작해도 되냐고 다시 묻지 않는다. 되돌릴 수 없거나 외부에 영향을 주는 행위만 승인 대상이다.

## 종료와 통합 보고

모든 단계가 끝나면 딥플로우가 마지막으로 확인한다:

1. **판단문에 답이 됐는가.** 안 됐으면 무엇이 부족한지, 다음 증거가 무엇인지 명시하고 부분완료로 보고한다.
2. **통합 보고 하나**를 만든다 — `배경 → 핵심 결론 → 상세 분석 → 권고/결론 → 한계·주의`. 각 단계의 산출물(딥서치 노션 기록, 딥솔루션 결정 브리프 등)을 중복 생성하지 않고 링크로 연결한다. 판정 상태(딥솔루션 상태 체계)와 기준일(KST)을 포함한다.
3. **저장은 각 스킬의 규칙을 따른다.** 딥서치 기록은 딥서치의 리서치·인사이트 DB 규칙, 통합 보고는 워크스페이스 기본 저장 규칙. 같은 내용을 여러 저장소에 복제하지 않는다.
4. 외부 쓰기·저장이 있었으면 재조회로 실제 상태를 확인한 뒤 완료라고 보고한다.

## 버전 규칙

V0.1은 베이스라인이다. 규칙 추가는 실전 사례(잘못된 라우팅, 끊긴 릴레이, 중복 실행, 과잉 발동)가 관측될 때만 하고, 발동 게이트의 오탐·미탐을 함께 기록해 다음 버전의 근거로 삼는다.
