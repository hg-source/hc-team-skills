# 면접준비 출력 규격

아래 예시는 가상 형식 설명이며 실제 지원자의 평가가 아니다. 모든 파일은 INTERVIEW_DIR에 UTF-8로 저장한다. 기존 파일을 교체할 때는 날짜가 붙은 백업을 먼저 남긴다.

## 질문 파일: 질문_<이름>.txt

```text
[맞춤형]
# 핵심성과 딥다이브
1. 이력서에 기재한 핵심성과의 시작 전 기준선과 목표는 무엇이었습니까?
   의도: 성과의 기간·기준선·본인 역할 검증
# 직무 전문성
2. 해당 직무에서 가장 어려웠던 의사결정의 대안과 선택 기준은 무엇이었습니까?
   의도: 직무 관련 판단과 트레이드오프 검증
[공통]
# 실행·협업
1. 의견이 갈린 프로젝트에서 본인이 직접 취한 행동과 결과는 무엇입니까?
   의도: 협업 행동의 구체적 증거 확인
```

- `[맞춤형]`/`[공통]`은 카테고리, `#` 줄은 그룹이다. 번호·불릿은 파서가 제거한다.
- 질문마다 바로 다음 줄에 `의도:`가 있어야 한다.
- 기본 전체 약 30문항, 공통 약 10문항. 요청한 분량이 있으면 그에 맞춘다.
- 핵심성과 딥다이브는 배경·목표 → 진단 → 판단·실행 → 성과·손익 → 본인기여 → 회고의 5~6문항으로 구성한다.
- 공통 질문·순서·행동기준은 같은 포지션 후보에게 동일하게 적용한다.

## 직무 파일: _position_<이름>.txt

실제 지원 직무를 한 줄로 쓴다. 명확하지 않으면 사용자에게 확인하고, 임의로 브랜드/마케팅 직무를 배정하지 않는다.

## AI 평가 파일: _ai_<이름>.json (선택)

```json
{
  "score": "산정 필요",
  "scoreMax": "100",
  "verdict": "보류",
  "source": "이력서·JD 기반 잠정 평가 (작성 도구, YYYY-MM-DD)",
  "info": { "연차": "확인 필요", "직무": "지원 직무" },
  "career": [
    { "co": "가상회사", "period": "2021.04~2023.12 (2년9개월)", "work": "직책·주요업무", "result": "지원자 주장과 검증 여부" }
  ],
  "key": "이력서 근거가 있는 강점",
  "concern": "근거 부족 또는 면접에서 확인할 부분",
  "basis": "실제 JD 요건별 점수 근거와 불확실성",
  "pass": "긍정 관점의 근거",
  "fail": "반대 관점의 근거 또는 보완점",
  "result": "■ 강점(근거)\n...\n\n■ 우려·리스크\n...\n\n■ 검증 필요(면접)\n..."
}
```

- 잠정 채점 기준: 직무적합 40 / 성과·역량 증거 30 / 경력 안정 15 / 전문·성장 15. JD 필수·우대요건이 기준이다. 근거가 부족하면 억지로 수치를 만들지 않는다.
- PASS/보류/FAIL은 면접 전 참고값이며 자동 채용·탈락 결정이 아니다. 경력의 공백이나 짧은 재직만으로 사유를 추정하지 않는다.
- 성별·나이·가족관계 등 직무와 무관한 민감 정보를 수집·추정·채점하지 않는다.
- `career[].period`에는 시작월~종료월과 포함월 근속기간을 함께 쓴다. 재직 중이면 기준월을 명시한다. 불명확한 날짜는 산정 필요로 둔다.
- 사용자가 평가를 원치 않으면 파일을 만들지 않는다. 기존 평가 파일은 삭제하지 말고 날짜 백업으로 옮긴다.

## PDF 연결: _pdfs_<이름>.json (필요할 때만)

```json
["홍길동 이력서.pdf", "홍길동 포트폴리오.pdf"]
```

INTERVIEW_DIR 안에 있는 실제 PDF 파일명만 쓴다. URL, 절대경로, 하위 경로는 허용하지 않는다. 원본 파일명은 유지한다. 동명이인·다른 직무 지원은 별도 후보 라벨을 확인해서 분리한다.
