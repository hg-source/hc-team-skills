# 공통 실행 규칙

Contract version: 1.1.0+dayflo.1

이 파일은 dayflo-local 배포 프로필의 공통 규칙이며 관련 스킬에 동일하게 포함된다. 수신 PC에서는 스킬 정본을 한 곳만 유지한다. 이 규칙은 모델·앱의 상위 지시, 사용자 요청, 실제 권한을 확대하지 않는다.

## 실행 전 짧게 확인

- 이 참조는 스킬 시작 시 읽는다. 스킬 ID·Version·실행 환경·쓰기 범위를 작업 기록에 남긴다. 간단한 조회라면 별도 파일 없이 답변으로 충분하다.
- 딥서치=이해와 발견, 딥솔루션=해결과 선택. 밤샘모드=사용자가 요청한 자율 실행 방식, 나혼랩=성장 후보·승인 관리. 딥플로우=이 스킬들의 선택·조합·릴레이를 지휘하는 오케스트레이션이며 내용 작업을 직접 하지 않는다. 실행 방식이나 지휘가 도메인의 근거·종료 기준을 덮어쓰지 않는다.
- 경로는 실제 로드된 스킬 폴더 기준으로 해석한다. 다른 스킬은 가용 목록의 ID로 찾아 읽고, 없으면 사용할 수 없다고 밝힌다. 읽지 않은 스킬을 실행했다고 하지 않는다.
- 각 환경의 실제 검색·파일·Notion 도구와 접근 범위를 확인한다. 연결된 것처럼 보이는 설정은 실행 증거가 아니다. 없는 도구·서브에이전트·로컬 드라이브를 가정하지 않는다.

## 환경별 차이 처리

| 환경 | 실행 원칙 |
|---|---|
| Codex / Claude Code | 현재 워크스페이스의 권한·저장 규칙과 정본 경로를 따른다. 연결 폴더나 캐시를 별도 정본으로 편집하지 않는다. |
| Claude Chat / Cowork | 설치된 플러그인의 상대 참조를 읽는다. Windows 경로가 보인다고 해당 PC에 접근 가능한 것은 아니다. 연결된 Notion과 허용된 작업 폴더를 사용한다. |
| Hermes | 실제 로드된 스킬을 확인한다. external_dirs는 읽기 전용 보안 경계가 아니다. 스킬 수정 요청이 없으면 원본을 수정하지 않는다. |

PowerShell이 없는 환경에서는 선택형 스캐폴드 스크립트를 실행하지 말고 같은 내용 기준으로 문서를 작성·검토한다. 도구 부재를 검증 성공으로 바꾸지 않는다. 장시간 실행은 앱의 세션·시간·도구 한도 안에서만 가능하다. 중단 시 재개 정보만 보존하며 자동 백그라운드 실행·예약을 약속하지 않는다.

## 저장과 승인

- 연구·저장 요청과 기존 지침이 승인한 기록만 수행한다. 고객 연락, Slack/메일 발송, 공개 게시, 구매, 삭제, 공유·권한·예약 변경은 별도 권한이 필요하다. 자기 자신에게 보내는 알림도 외부 발송이다. 승인된 대상·내용 범위가 있으면 중복 확인은 하지 않는다.
- 기본 결과물 저장은 현재 워크스페이스의 로컬 개인 영역이다. Notion 등 외부 저장은 수신자가 연결하고 승인한 경우에만 사용한다. 팀/공용 저장을 명시할 때만 그 범위로 저장하며 개인 근거를 자동 복사하지 않는다.
- 이 배포본에는 계정·데이터베이스 연결이 없다. 미연결 상태에서는 외부 DB 조회·생성·쓰기를 시도하지 않는다. 수신자가 별도 설정하고 승인한 연결만 사용한다.
- 외부 저장이 설정·승인된 경우 저장 전에 실제 스키마·권한을 조회한다. 일반 결과물에는 실제 작업도구와 유효한 분류 옵션을 기록한다. 기존 태그·관계와 사용자 입력은 보존한다. 앱별 도구명 차이는 현재 도구 스키마에 맞추며, 이름만 바꿔 성공을 가정하지 않는다.
- 접근 실패나 검색 미검출로 새 DB를 만들지 않는다. 미연결이면 현재 환경의 허용된 로컬 폴더에 보관하거나 다운로드 가능한 결과를 제공한다. 로컬 파일 도구도 없으면 대화에 보존하고 저장 미완료를 알린다.
- 요청 전 실패는 `미전송`, 전송 후 타임아웃은 `전송 결과 미확인`이다. 후자는 대상 재조회 전 재전송하지 않는다. 저장 완료는 본문·속성·관계 재조회로 확인하고 실제 URL을 제공한다.

## 동시 작업과 재개

- 실행마다 별도 `run_id`와 작업 폴더를 사용한다. 재개는 같은 과제의 run_id와 목표를 확인한 경우만 한다. 다른 작업의 STATE 파일을 이어받거나 덮어쓰지 않는다. 같은 과제에 여러 스킬을 조합하면 기존 상태 파일을 재사용한다.
- 서로 다른 기록은 병행할 수 있다. 같은 연구/인사이트/레벨 후보의 최종 쓰기는 담당 실행 하나만 수행한다. 여러 앱에서 같은 과제를 동시에 진행한다면 사용자 지정 또는 공유된 인계 기록으로 담당을 확인한다. 지정되지 않은 실행은 초안만 만들고 최종 쓰기를 보류한다.
- 키/기존 URL로 조회한 뒤 기록 직전 최신 내용을 다시 읽고 좁게 수정한다. 변경을 발견하면 자동 덮어쓰기하지 말고 대조한다. Notion은 이 절차에 원자적 잠금·유일성 제약을 제공한다고 가정하지 않는다. 담당 지정과 재조회도 완전한 동시성 보장은 아니다.
- 같은 후보의 레벨 승인은 반복 요청에도 한 번만 반영한다. 후보의 현재 상태·사용자 승인 기록을 재조회하고, 이미 확정/승인된 정정이면 숫자를 다시 올리지 않는다. 승인할 때 최신 원장을 기준으로 계산하고 다른 승인과 직렬 처리한다.

## 완료와 업데이트

근거·미확인·추정을 구분하고 과제의 완료 기준을 만족하면 끝낸다. 출처 개수·새 인사이트·참신함을 채우기 위해 사실을 만들거나 불필요한 일을 늘리지 않는다. 원본 수정, 패키지 생성, 앱 설치, 실제 호출·저장 검증은 서로 다른 상태로 보고한다. 갱신 후에는 새 대화에서 실제 스킬 버전과 핵심 흐름을 확인한다. 모델별 표현·추론 결과의 완전한 동일성은 보장하지 않는다.

## 로컬 저장 계약

기존 결과물 루트와 원장을 먼저 찾아 재사용한다. 없으면 허용된 로컬 폴더에 고유 run_id로 기록한다. 동일 키를 먼저 조회하고 기존 파일을 다시 읽은 뒤 좁게 갱신하며 이전 판단을 보존한다. 결과는 실제 파일을 다시 열어 확인한다. 미연결 외부 저장소를 성공했다고 보고하지 않는다.
