# 두 DB의 저장·재사용 계약

`../connections.json`은 미연결 기본값이다. 수신자가 승인한 외부 연결을 별도로 설정한 경우에만 현재 커넥터의 실제 도구와 스키마를 확인한다. 토큰·계정 ID·페이지 URL은 스킬이나 저장소에 넣지 않는다. 속성 자동값과 읽기 전용값은 쓰지 않는다.

## 먼저 저장 모드 선택

외부 저장이 활성화되지 않았으면 아래 DB 절차를 실행하지 않는다. 기존 로컬 리서치·인사이트 기록을 키와 내용으로 찾아 재사용하고, 없으면 승인된 작업 폴더에 파일로 생성한다. 안정된 키·관련 기록 경로·근거·변경 이력을 남기고 저장 후 다시 읽는다.

아래 속성과 절차는 외부 저장 모드가 설정·승인됐을 때의 계약이다.

## 속성

리서치 DB: `이름`(제목), `조사키`(텍스트), `분야`(시장/경쟁/고객/트렌드 다중선택), `상태`(진행중/조사완료/부분완료), `기준일`(날짜), `결론`(짧은 텍스트), `관련인사이트`(양방향 관계), `업데이트`(자동).

인사이트 DB: `이름`(발견/가설 제목), `인사이트키`(텍스트), `상태`(관찰/검증중/잠정지지/반박/보류), `관련리서치`(양방향 관계), `다음검증`(짧은 텍스트), `업데이트`(자동).

`조사완료`는 정한 범위의 조사 완료일 뿐 가설의 확정이 아니다. 관찰 후보는 기본적으로 리서치 본문에 둔다. 재사용 가치가 있어 분리할 때만 인사이트 행을 만든다. `잠정지지`를 보편적 사실이나 출시 승인으로 설명하지 않는다.

## 조회→쓰기→재조회

1. 두 DB 스키마를 읽는다. 전체 접근 실패와 특정 조건의 조회 0건을 구분한다.
2. 기존 기록을 키와 의미로 검색한다. 키는 조사 주제·시장·범위 또는 인사이트의 대상·문제·기제를 반영한 안정된 문자열이다. 제목 변경이나 단순 후속 업데이트 때문에 새 키/날짜 접미사를 만들지 않는다. 명확히 다른 조사 사이클은 별도 기록으로 연결할 수 있다.
3. SQL 지원 시 `SELECT url, "이름", "조사키" FROM "collection://<research_id>" WHERE "조사키" = ?`처럼 매개변수를 사용한다. 인사이트는 `인사이트키`로 조회한다. 비슷한 표현은 제목/본문 의미 검색과 실제 페이지 확인을 보완한다. SQL 불가 시 Notion 검색→후보 fetch로 대체하고 검색의 한계를 표시한다.
4. 1개가 맞으면 업데이트한다. 여러 개가 겹치면 각각 읽어 정본을 식별한다. 자동 삭제/병합은 하지 않는다. 조회가 실패했다면 신규 생성을 강행하지 않는다.
5. 기록 직전 최신 본문을 읽고 필요한 부분만 수정한다. 다른 작업의 새 내용을 덮어쓰지 않는다. 기존 관계 목록에 새 관계를 합치고, 재인용 원자료·동일 URL은 중복 근거로 세지 않는다.
6. 새 기록은 조회 후 생성한다. 전송 시간초과나 불명확한 응답 후에는 동일 키로 재조회하고, 생성 결과가 확인될 때까지 무작정 재시도하지 않는다.
7. 리서치와 인사이트를 연결하고 각 페이지를 다시 읽어 본문·상태·관계·URL을 검증한다. 관계 하나를 쓰면 반대편도 자동 반영되는 양방향 관계이므로 불필요한 이중 쓰기를 피한다.

키는 Notion에서 유일성 제약이 걸린 필드가 아니다. 중복 방지는 애플리케이션 절차다. 동일 조사에 대한 쓰기는 한 실행자가 맡고 병렬 중복 생성하지 않는다. 중요한 반복 처리에서는 저장 후 동일 키의 건수도 확인한다.

## 본문

공통 순서: 배경 → 핵심 결론 → 상세 분석 → 권고/결론 → 한계·주의.

리서치의 상세 분석에는 근거별 ID·URL·해당 위치·확인 내용·해석·한계를 담는다. 검색어/자료원/확인일, 제외·미접근 자료, 경쟁 가설, 종료 이유를 필요에 맞게 뒤에 둔다. 원문을 장문 복제하지 않는다.

인사이트에는 핵심 발견, 적용 조건, 지지·반대 근거가 있는 리서치 링크, 다음 검증을 담는다. 후속 업데이트는 날짜·이전 판단·새 근거·변경 판단·미해결 항목을 보존한다. 현재 요약을 수정하더라도 과거 예측을 소급해 고치지 않는다.

## 도구 형식

현재 도구가 제공하는 Notion Markdown 규격을 확인하고, 별도 규격이 없으면 해당 도구 스키마가 지원하는 기본 형식만 사용한다. 일부 커넥터에서는 날짜를 `date:기준일:start`와 `date:기준일:is_datetime`으로 쓰며, 다중선택은 JSON 배열 문자열, 관계는 페이지 ID/URL 배열을 사용할 수 있다. 이 예시를 다른 도구에 그대로 적용하지 말고 항상 현재 도구 스키마를 따른다. 실험/조사 결과 본문과 AI 작업로그의 한 줄 기록을 혼동하지 않는다.

새 DB 자동 생성·스키마 확대·공유 범위 변경은 하지 않는다. 로컬 저장을 기본으로 사용하고 사용자가 외부 개인·팀·공용 저장을 지정하면 먼저 대상과 접근 범위를 확인한다. 팀 요청에 다른 저장소로 조용히 대체 저장하지 않는다.
